# Release Notes — CIM v1.3.0

**Release Date:** 2026-06-15  
**Type:** Feature Release — Intelligence Differentiation & Explainability Layer  
**Breaking Changes:** None  

---

## Overview

CIM v1.3.0 completes the intelligence differentiation initiative started in v1.1. The pipeline is now capable of producing explainable, evidence-backed competitive intelligence that goes beyond surface-level summarization. This release is the foundation for the SaaS launch and portfolio documentation.

---

## What's New

### Signal Preservation Engine (v1.1)

- **Root cause fixed**: Production was discarding 80–90% of content before signal extraction due to a 12k-character context truncation applied *before* `extract_signals()`. Fixed by routing full cleaned content through the extraction pipeline.
- **Before**: OpenAI — 9 production signals vs 48 replay signals. Google — 7 production signals vs 76 replay signals.
- **After**: Full signal preservation verified across all three benchmark companies.
- New `noise_ratio` / `signal_ratio` metrics per page (`pipeline_diff.py`).

### Strategic Interpretation (v1.2)

- All intelligence agents now interpret *why* a company behaves the way it does, not just *what* it does.
- New fields in every analysis: `strategic_direction`, `commercial_signal`, `expansion_signal`, `defensibility_signal`, `market_position`.
- Tone classification upgraded from single word (e.g. `"technical"`) to multi-signal string (e.g. `"Developer-First, Platform Ecosystem"`).
- ICP now combines industry × company size × buyer persona × end user in a structured sentence.

### Competitor DNA (v1.2.1)

- New `competitor_dna` block in every analysis:
  - `archetype` — strategic identity label (e.g. "AI Platform Builder", "Trusted Enterprise AI")
  - `growth_model` — how the company grows
  - `primary_moat` — key defensibility mechanism
  - `strategic_risk` — primary risk to current strategy
  - `expansion_vector` — directional hypothesis for next expansion
  - `likely_next_moves` — 3 prioritized hypotheses with confidence levels
  - `alternative_archetypes` — competing archetypes with confidence scores

### Evidence-Based Archetype Scoring (v1.2.2)

- Archetypes are no longer guessed — they emerge from evidence.
- New `archetype_scoring.py` scores 8 archetype templates using signal keywords weighted by source type.
- New `archetype_registry.py` defines the keyword taxonomy for each archetype.
- Produces `archetype` + `confidence` + `supporting_signals` + `alternative_archetypes` from any company's extracted signals.
- No hardcoded company-specific logic — works on any competitor.

### Evidence-Based Confidence Engine (v1.2.3)

- **Core change**: Confidence scores are now computed by Python, not generated by LLMs.
- Every confidence score is now explainable: `confidence = f(evidence_count, source_diversity, agreement_score)`.
- New modules:
  - `evidence_registry.py` — centralizes evidence collection during synthesis
  - `agreement_score.py` — Jaccard-based semantic overlap between evidence statements
  - `confidence_engine.py` — deterministic scoring from evidence volume and source diversity
  - `archetype_calibration.py` — evidence-based weighting adjustments for archetype confidence
- New `confidence_metrics` field in every analysis — one entry per intelligence field, with `confidence`, `evidence_count`, `source_count`, `source_types`, `agreement_score`.
- Legacy `confidence_scores` field preserved for backward compatibility.

### Explainability Layer (v1.3.0 — Production Integration)

- All new intelligence fields are now integrated end-to-end: pipeline → schema → DB → API → frontend.
- Frontend gains three new collapsible sections per competitor (default collapsed):
  - **Competitor DNA** — archetype badge, confidence bar, supporting signals, growth model, moat, risk, expansion vector, likely next moves, alternative archetypes
  - **Strategic Interpretation** — strategic direction, commercial signal, expansion signal, defensibility, market position
  - **Intelligence Confidence** — per-field evidence table with confidence %, evidence count, source count, agreement score
- All new UI sections use optional chaining — pre-v1.2.x reports render identically with no errors.

## Bug Fixes

- Fixed Anthropic Haiku parse failure caused by prepended markdown text before JSON output — orchestrator now extracts JSON between first `{` and last `}`.
- Fixed `competitor_dna` being silently dropped when synthesis LLM omitted it — orchestrator now unconditionally writes it from the calibrated archetype result.
- Fixed `confidence_metrics` field name mismatch (`CompetitorAnalysis` schema was missing this field, causing it to be silently discarded post-synthesis).
- Fixed missing `archetype` key in `agent_outputs` — calibrated archetype dict is now persisted in the database.
- Removed debug `print("RAW LLM Output: ...")` statement from production orchestrator.

---

## Known Limitations

- Anthropic (Claude Haiku) occasionally hits token limits when generating full evidence arrays for large competitor sites. Mitigated by limiting evidence to 2 quotes per field in the synthesis prompt.
- `likely_next_moves` may be empty for Anthropic analysis if the Claude Haiku synthesis call times out — artifact-based tests will skip gracefully in this case.
- `agreement_score` currently uses Jaccard similarity (word overlap). Future releases will upgrade to embedding-based semantic similarity for higher accuracy.
- `strategic_interpretation` depends on the synthesis LLM including it in the output — it is not yet computed deterministically by Python.

---

## Migration Notes for Operators

- **No schema migration required** — all new fields default to `{}` / `[]`. Existing records in Postgres will deserialize cleanly.
- **No API breaking changes** — all new fields are additive to `GET /api/report/{run_id}`.
- **Frontend** — no action required. Old reports will render identically; new sections only appear when `competitor_dna`, `strategic_interpretation`, and `confidence_metrics` are present.
- **Environment variables** — no new variables required. Existing `OPENROUTER_API_KEY` covers all LLM calls.
